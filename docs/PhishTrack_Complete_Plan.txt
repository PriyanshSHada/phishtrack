3. DATABASE SCHEMA
================================================================

--- USERS TABLE ---
  id              UUID (Primary Key)
  name            VARCHAR
  email           VARCHAR (unique)
  password        VARCHAR (bcrypt hashed)
  analyst_id      VARCHAR (auto: PSH-001)
  organization    VARCHAR
  role            ENUM (analyst / admin)
  device_id       VARCHAR (device binding)
  is_verified     BOOLEAN
  created_at      TIMESTAMP
  last_login      TIMESTAMP

--- CASES TABLE ---
  id              UUID (Primary Key)
  case_number     VARCHAR (auto: CASE-2025-001)
  user_id         UUID (Foreign Key → users)
  url             TEXT (phishing link)
  description     TEXT
  source          ENUM (WhatsApp / Email / SMS / Other)
  priority        ENUM (Low / Medium / High / Critical)
  status          ENUM (Open / Investigating / Closed)
  tags            TEXT[]
  created_at      TIMESTAMP
  updated_at      TIMESTAMP

--- ANALYSIS TABLE ---
  id              UUID (Primary Key)
  case_id         UUID (Foreign Key → cases)
  threat_score    INTEGER (0-100)
  severity        ENUM (Low / Medium / High / Critical)
  whois_data      JSONB
  ip_geolocation  JSONB
  ssl_info        JSONB
  redirect_chain  TEXT[]
  virustotal_result JSONB
  page_screenshot TEXT (base64 / Cloudinary URL)
  page_source_hash VARCHAR (SHA-256)
  ai_summary      TEXT
  ai_indicators   TEXT[]
  ai_techniques   TEXT[]
  analyzed_at     TIMESTAMP
  sandbox_version VARCHAR

--- REPORTS TABLE ---
  id              UUID (Primary Key)
  case_id         UUID (Foreign Key → cases)
  version         INTEGER (1, 2, 3...)
  pdf_url         TEXT
  digital_signature TEXT (SHA-256 hash)
  generated_by    UUID (Foreign Key → users)
  generated_at    TIMESTAMP
  is_tampered     BOOLEAN (default: false)

--- AUDIT LOGS TABLE ---
  id              UUID (Primary Key)
  user_id         UUID (Foreign Key → users)
  case_id         UUID (Foreign Key → cases)
  action          VARCHAR (CASE_CREATED / ANALYZED / REPORT_GENERATED...)
  ip_address      VARCHAR
  device_id       VARCHAR
  timestamp       TIMESTAMP
  metadata        JSONB

--- CHAIN OF CUSTODY TABLE ---
  id              UUID (Primary Key)
  case_id         UUID (Foreign Key → cases)
  user_id         UUID (Foreign Key → users)
  action          VARCHAR
  timestamp       TIMESTAMP
  hash_before     VARCHAR (SHA-256)
  hash_after      VARCHAR (SHA-256)

5. ANALYSIS ENGINE — STEP BY STEP FLOW
================================================================

Step 1: User submits phishing URL from Android app

Step 2: Backend receives POST /api/analysis/run
        → Validates URL format
        → Checks against blocklist
        → Logs action in audit_logs

Step 3: Run 6 checks IN PARALLEL:

        [1] WHOIS Lookup
            → Domain registration date
            → Registrar info
            → Owner country
            → Expiry date
            → Flag: domain < 30 days old = suspicious

        [2] IP Geolocation
            → Resolve domain to IP
            → Get country, city, ISP
            → Flag: hosted in known abuse countries

        [3] SSL Certificate Check
            → Is SSL present?
            → Is it self-signed?
            → Is it expired?
            → Does domain match cert?

        [4] VirusTotal API Scan
            → Check URL against 70+ antivirus engines
            → Get malicious / suspicious / clean counts
            → Get detection names

        [5] Docker Sandbox → Puppeteer
            → Launch isolated Docker container
            → Puppeteer opens URL in headless Chrome
            → Capture: full page screenshot
            → Capture: complete HTML source
            → Detect: login forms / password fields
            → Trace: full redirect chain
            → Hash page source (SHA-256)
            → Destroy container after 10 seconds

        [6] Similar Domain Detection
            → Compare to top 1000 brand domains
            → Levenshtein distance check
            → Flag: "Looks like hdfc.com"

Step 4: Combine all results
        → Send to GPT-4o API with system prompt:
          "You are a professional phishing analyst.
           Analyze the following data and return a
           structured JSON report with threat score,
           severity, indicators, techniques, and summary."

Step 5: GPT-4o returns:
        → threat_score (0-100)
        → severity (Low/Medium/High/Critical)
        → indicators[] (list of suspicious signs)
        → techniques[] (typosquatting, form hijacking, etc.)
        → ai_summary (human-readable paragraph)

Step 6: Save all results to analysis table
        → Update case status to "Investigating"
        → Log in chain_of_custody
        → Return complete result to Android app

6. DOCKER SANDBOX — SAFETY CONFIGURATION
================================================================

Container Settings:
  Base image        : node:18-alpine + chromium
  Network mode      : bridge (isolated)
  Read-only FS      : true (no writes to host)
  Memory limit      : 256MB
  CPU limit         : 0.5 cores
  Execution timeout : 10 seconds max
  Auto-destroy      : container killed after each run

Safety Checks Before Launch:
  → URL must start with http:// or https://
  → Domain checked against blocklist (known malware)
  → IP range check (block private IPs: 192.168.x.x etc.)
  → Max redirects: 5

What Puppeteer Collects:
  → Full page HTML source
  → Screenshot (PNG, full page)
  → All form elements and input types
  → All redirect URLs in chain
  → Final landing URL
  → Page title and meta tags

13. RISK & MITIGATION
================================================================

  RISK: Malware/exploit from phishing site
  SOLUTION: Docker container fully isolated, auto-destroyed after run,
            no persistent storage, no host network access

  RISK: OpenAI API cost overrun
  SOLUTION: Cache results for repeated URLs (Redis 24hr TTL),
            limit 10 free analyses per user per day

  RISK: VirusTotal rate limit (4 req/min free)
  SOLUTION: Cache VT results in DB for 24 hours per URL

  RISK: Report tampering / evidence integrity
  SOLUTION: SHA-256 hash of report at generation, stored separately,
            verify endpoint checks hash on demand

  RISK: App used offline
  SOLUTION: Room Database caches all cases locally, syncs on reconnect

  RISK: Legal issues with phishing analysis tool
  SOLUTION: Tool is analysis-only, no attack capability, clearly
            labeled as forensic investigation tool
